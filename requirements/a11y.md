# A11Y — accessibility of the UI

Requirements for the access that assistive technology (for example a screen
reader) has to a swindowzig UI.

## REQ-A11Y-001 — The web build mirrors the semantic tree into the DOM

- **Status:** active
- **Source:** sean
- **Origin:** #15
- **Type:** functional
- **Priority:** P1
- **Statement:** When the sw_ui semantic tree changes, the web build shall
  update a hidden DOM tree that has one element for each semantic node, with
  the DOM role of the node and its accessible name.
- **Rationale:** A canvas has no DOM, so a screen reader finds nothing in a
  canvas UI. The DOM roles are: a button is a `<button>`, a list is a `<ul>`
  with `<li>` items, a text field is an `<input>` with a label. The decision
  for Same Again Please is to mirror the tree into the DOM.
- **Verification:** Test — `backends/wasm/tests/a11y.pw.ts` › "the semantic
  tree of flat2d is in the accessibility tree"
- **Relations:** none

## REQ-A11Y-002 — The DOM focus follows the focus of the game

- **Status:** active
- **Source:** sean
- **Origin:** #15
- **Type:** functional
- **Priority:** P1
- **Statement:** While a semantic node has focus, the web build shall give DOM
  focus to the DOM element of that node.
- **Rationale:** A screen reader reads the element that has DOM focus. The
  game moves its focus with Tab and the arrow keys, and the screen reader
  must follow it. For a text field with text input on, the element is the
  hidden input-method `<input>`, which gets the name of the field.
- **Verification:** Test — `backends/wasm/tests/a11y.pw.ts` › "the semantic
  tree of flat2d is in the accessibility tree"
- **Relations:** depends-on REQ-A11Y-001

## REQ-A11Y-003 — A live region is an aria-live element

- **Status:** active
- **Source:** sean
- **Origin:** #15
- **Type:** functional
- **Priority:** P1
- **Statement:** Where a semantic node is a live region, the web build shall
  mirror it as an element with `aria-live="polite"`.
- **Rationale:** A screen reader then speaks a change of a status text, for
  example "Accent: Orange", without a move of the focus.
- **Verification:** Test — `backends/wasm/tests/a11y.pw.ts` › "the semantic
  tree of flat2d is in the accessibility tree"
- **Relations:** depends-on REQ-A11Y-001

## REQ-A11Y-004 — The mirror is visually hidden

- **Status:** active
- **Source:** sean
- **Origin:** #15
- **Type:** constraint
- **Priority:** P1
- **Statement:** The web build shall hide the DOM mirror with the standard
  visually-hidden CSS (clip to a 1 px box), not with `display: none`.
- **Rationale:** The browser removes an element with `display: none` from the
  accessibility tree, and such an element cannot take focus.
- **Verification:** Test — `backends/wasm/tests/a11y.pw.ts` › "the semantic
  tree of flat2d is in the accessibility tree"
- **Relations:** depends-on REQ-A11Y-001

## REQ-A11Y-005 — An unchanged tree is not sent to JS

- **Status:** active
- **Source:** sean
- **Origin:** #15
- **Type:** quality
- **Priority:** P1
- **Statement:** If the encoded semantic tree of a frame is equal to the last
  tree sent, then the web build shall not send it to JS.
- **Rationale:** The mirror must not slow the frame. A frame with no change
  costs one encode and one hash, and no DOM work.
- **Verification:** Test — `libs/sw_ui/src/web_mirror.zig` › "web mirror:
  update is true only when the tree changes"
- **Relations:** refines REQ-A11Y-001
